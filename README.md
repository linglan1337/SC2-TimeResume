> 用于在**自有测试环境**中研究 StarCraft II 暂停机制。

## 项目背景

在网络对局中曾出现有人利用暂停机制持续冻结游戏、导致其他人无法正常进行的情况。
本项目从纯技术角度验证：**客户端可以调用游戏内部的恢复入口，并观察其效果**。

本项目不解决“如何识别作弊者”——那需要服务端与录像分析，不在客户端程序的能力范围内。

## 功能

| 功能 | 说明 |
| --- | --- |
| 进程实时检测 | 底部状态栏每 500ms 扫描一次，显示游戏是否运行及 PID |
| 解除暂停 | 向游戏进程调用内置恢复入口，高频执行 |
| 自定义时长 | 1–600 秒可调，默认 5 秒 |
| 中途停止 | 运行中再点同一按钮即可立即停止 |
| 版本锁定 | 三重校验（文件名 + 文件哈希 + 入口指令字节），版本不符直接拒绝 |

界面只有一个按钮：**点击解除时间暂停**。

## 编译

### 方式一：脚本

```powershell
powershell -ExecutionPolicy Bypass -File .\build\build.ps1
```

输出到 `build\output\SC2TimeResume.exe`。

> 若直接 `.\build\build.ps1` 提示“禁止运行脚本”，用上面这条带
> `-ExecutionPolicy Bypass` 的命令即可，无需修改系统设置。

### 方式二：手动

```bat
csc /platform:x64 /target:winexe /optimize+ ^
    /reference:System.Windows.Forms.dll ^
    /reference:System.Drawing.dll ^
    /reference:System.Security.dll ^
    /reference:System.Management.dll ^
    /out:SC2TimeResume.exe src\SC2TimeResume.cs
```

**运行环境**：Windows 10 / 11，.NET Framework 4.0 或更高（系统自带）。
编译器 `csc.exe` 位于 `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\`。

## 使用

1. 确认游戏版本为 **5.0.15.98370（Base98370）**，否则程序会拒绝运行。
2. **以高完整性运行**：本机 UAC 关闭时双击即可；否则用
   *任务管理器 → 文件 → 运行新任务 → 勾选「以系统管理权限创建此任务」*。
3. 启动后状态栏应显示绿色 `SC2运行中 · PID xxxx`。
4. 设置持续时长，点击按钮；运行中再点一次可立即停止。

> **重要**：exe 必须放在**不受沙箱限制的目录**（如 `C:\Tools\`）。
> 放在某些受策略限制的工作目录下运行时，进程会被降为低完整性，
> 导致看不到游戏进程（状态栏会提示“进程视图受限”）。

## 版本适配

游戏每次更新都可能改变函数入口地址。换版本时**必须重新定位**，
否则程序会因签名校验失败而拒绝运行（这是有意的安全保护，
防止把旧地址用到新版本上导致崩溃）。

定位流程见 [docs/REVERSE_ENGINEERING.md](docs/REVERSE_ENGINEERING.md)。

需要更新的常量位于 `SC2TimeResume.cs` 顶部：

```csharp
ExpectedVersion                       // 版本号
ExpectedSha256                        // SC2_x64.exe 的 SHA-256
ResumeRva                             // 恢复入口的 RVA
ResumeFileOffset                      // 同一入口在文件中的偏移
ResumePrefix                          // 入口处 25 字节指令指纹
```

## 已知限制

- 只对源码中记录的单一构建有效，不支持多版本。
- 游戏内部对暂停/恢复可能有状态机与节流，高频调用**不保证**能压过对手的持续暂停。
- 调用成功只代表本机成功发起了调用，**不代表其他客户端会同步**。
- 高频创建线程可能造成游戏卡顿，建议先用较短时长试。
